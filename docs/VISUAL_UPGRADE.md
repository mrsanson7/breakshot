# Break Shot 외형 업그레이드 (three.js 유지 + Blender 모델)

이 문서는 `docs/VISUAL_UPGRADE.md` 로 저장소에 넣고 Claude Code에 작업을 맡길 때 쓰는 지시서입니다.

## 목표

물리, 규칙, 서버, 네트워크 코드는 건드리지 않고 **화면에 보이는 것만** Blender로 만든 glTF(.glb) 모델로 바꾼다.
모델 파일이 없거나 불러오기에 실패하면 지금의 코드 생성 그래픽이 그대로 나와야 한다.

## 절대 바꾸지 않는 것

- `packages/shared/**` 전체 (물리, 규칙, 설정값, 메시지)
- `packages/server/**` 전체
- 공(ball) 메시: 지금처럼 `SphereGeometry` + `ballTexture()` 유지. 물리 반지름과 화면이 정확히 같아야 한다.
- 펠트 바닥면(z = 0)과 쿠션 노즈 선: `geom.segments`, `geom.pockets` 에서 만드는 지금 코드 유지. 공이 실제로 부딪히는 면이므로 모델로 대체하지 않는다.
- 조준선, 궤적, 링, 하이라이트 같은 오버레이
- `pnpm test` 88개 전부 통과 상태 유지

## 바꾸는 것 (단계별)

### 1단계 — 위험 없는 것부터: 당구장 공간, 조명, 테이블 다리

- `packages/client/public/models/room.glb`: 바닥, 벽 일부, 테이블 위 갓등. 테이블 종류와 상관없이 하나.
- `packages/client/public/models/legs-<tableId>.glb`: 테이블 다리와 에이프런 아래 받침. 테이블 종류마다 크기가 다르므로 종류별로.
- 갓등 위치에 맞춰 지금의 `DirectionalLight` 위치를 조정하되, 그림자 범위(`sun.shadow.camera`)는 그대로 둔다.
- 위 시점(top)에서는 room을 숨기거나 어둡게 해서 테이블이 가려지지 않게 한다.

### 2단계 — 큐

- `packages/client/public/models/cue.glb` 하나로 지금의 `buildCue()` 원통 조합을 대체한다.
- 모델 규칙: 원점 = 큐 팁 끝, 큐는 +Y 방향으로 뻗음(지금 `buildCue()` 와 같은 축), 전체 길이 `RENDER3D.cue.length`(1.45 m), 팁 반지름 `tipRadius`, 버트 반지름 `buttRadius` 에 맞춤.
- 상대 큐는 반투명(`ghost`)으로 그려야 하므로, 불러온 모든 머티리얼을 `transparent: true` 로 복제해 `cueMaterials` 에 넣는다.
- 큐 각도(0~60°), 당점에 따른 팁 위치, 파워에 따른 당김은 기존 코드 그대로 동작해야 한다.

### 3단계 — 레일(나무 프레임)과 포켓 장식

- 레일은 포켓 위치와 쿠션 뒷선에 맞물려야 해서 가장 까다롭다. 테이블 종류별로 따로 만든다.
  - `rail-pool.glb` (포켓볼), `rail-carom-large.glb` (3쿠션 대대), `rail-carom-mid.glb` (4구 중대) — 실제 테이블 id는 `shared/src/config/tables.ts` 에서 확인
- 레일 안쪽 개구부는 지금 `railOpening()` 이 만드는 윤곽과 같아야 한다. Blender 작업 전에 이 윤곽과 쿠션 뒷선, 포켓 원을 테이블별 SVG(또는 JSON 좌표)로 뽑아서 Blender 밑그림으로 쓴다. 이 내보내기 스크립트도 함께 만든다.
- 다이아몬드는 지금처럼 `geom.diamonds` 좌표로 코드에서 찍는다(위치가 규칙 시스템과 연결됨). 모델에는 다이아몬드를 넣지 않는다.
- 포켓볼 테이블: 포켓 가죽 커버/금속 모서리는 포켓 원 좌표에 맞춰 장식 모델로 얹는다.
- 검증: 불러온 레일 모델의 안쪽 경계가 `railOpening()` 윤곽에서 2 mm 이상 벗어나면 콘솔 경고를 내고 코드 생성 레일을 쓴다. 이 검사는 개발 모드에서만 돈다.

## 좌표와 단위

- 게임 월드: x = 테이블 길이 방향, y = 폭 방향, **z = 위**, 단위 m, 펠트 면이 z = 0, 테이블 원점 = 한쪽 모서리 (L/2, W/2 가 중심).
- glTF는 Y가 위이므로, 불러온 루트에 X축 +90° 회전을 한 번만 적용한다. 이 변환은 로더 한 곳에만 둔다.
- Blender에서는 미터 단위, 스케일 1, 변환 적용(Apply All Transforms) 후 내보낸다. 원점 규칙은 위 각 단계에 적힌 대로.

## 불러오기 구조

- 새 파일 `packages/client/src/render3d/models.ts`: `GLTFLoader` 로 모델을 비동기로 불러오고, 실패하면 `null` 반환.
- 게임은 지금처럼 바로 시작하고, 모델이 도착하면 해당 부분만 교체한다(로딩 화면으로 막지 않기).
- 모델 경로와 켜고 끄기는 `packages/client/src/config.ts` 의 새 `MODELS` 설정에만 둔다(수치는 config에만 있다는 기존 원칙 유지).
- `?models=off` 쿼리나 설정으로 모델을 끄고 기존 그래픽과 비교할 수 있게 한다.

## 용량과 성능 (휴대폰 세로 화면 기준)

- 모델 전체 합계 5 MB 이하, 테이블 하나 기준 삼각형 10만 개 이하를 목표로 한다.
- 텍스처는 2048 px 이하. Meshopt나 Draco 압축을 쓰면 해당 디코더 설정도 함께 넣는다.
- 그림자는 공과 큐만 드리우고(`castShadow`), 레일·방은 받기만 한다.
- 작업 전후로 같은 휴대폰에서 프레임 차이를 확인하고 결과를 README에 적는다.

## 모델 출처

- 직접 Blender로 만든 모델을 우선한다.
- 소품(갓등, 의자, 초크 등)은 Tripo·Meshy 같은 생성 서비스 무료 크레딧으로 초안을 뽑아도 되지만, Blender에서 폴리곤을 줄이고 크기·방향을 맞춘 뒤 넣는다.
- 출처와 라이선스를 `packages/client/public/models/CREDITS.md` 에 파일별로 적는다. 생성형 모델이 들어가면 그 사실도 적는다.

## 완료 확인

| 단계 | 확인할 것 |
|----|----|
| 1 | 세 종목 모두 방·조명·다리가 보이고, 위 시점에서 테이블이 가려지지 않음. `?models=off` 에서 이전과 같음 |
| 2 | 큐 뒤 시점에서 큐 각도·당점·파워가 이전과 똑같이 보이고, 상대 큐가 반투명 |
| 3 | 레일이 쿠션·포켓과 틈 없이 맞물림. 공이 쿠션에 닿는 위치가 화면상으로도 정확 |
| 전체 | `pnpm test`, `pnpm typecheck`, `pnpm build` 통과. 휴대폰 세로 화면에서 터치 플레이 정상 |

## 작업 방식

- 단계마다 따로 커밋하고, 각 단계가 끝나면 직접 실행해서 확인한 뒤에 다 됐다고 말한다.
- 이 문서에 없는 부분을 바꿔야 하면 먼저 물어본다.
- Blender 작업이 필요한 부분은 (Blender MCP가 연결돼 있으면) 직접 만들고, 아니면 Blender에서 할 일을 단계별로 적어서 나에게 넘긴다.
